# SpaceBat

Site for the SpaceBat show. Comic-book catalog, hosts, and a podcast page.

Live: [www.spacebatshow.net](https://www.spacebatshow.net)

The conversation is comics, movies, tech, politics, markets, and finance. The NASA STS-119 bat is tongue-in-cheek inspiration, not the plot.

`/movies` lists movies and TV from `media_item`. Migration `0012_media.sql` creates that table, `media_rating`, and a `media_seed` marker, then inserts the original 43 catalog titles once. Migration `0013_media_space_odyssey.sql` adds 2001: A Space Odyssey once. Migration `0014_media_rescan.sql` adds the 2026-11-01 rescan titles once. Both run on a database that already has the earlier titles, and neither changes existing rows or ratings. Deleting a title does not bring it back. Admins edit the list at `/admin/movies`. Posters and details prefer TMDB when `TMDB_API_KEY` is set. That value is a v4 read-access token sent as a bearer, unless it is a 32-character hex v3 api_key. Wikipedia and IMDb stay as backups. Without that key the seeded list still renders. John (`jack2ryan@aim.com`) and Dan (`dstrack@hotmail.com`) each set only their own rating.

Show-day mail goes out from the hourly cron `GET /api/alerts/run` (`15 * * * *` in `vercel.json`), authorized with `Authorization: Bearer $CRON_SECRET`. The standing show is Wednesday at 8:30 PM America/New_York, including across EDT and EST. Ordinary weeks need no row and no deploy. Podhome's pending live item only fills in that night's title and start time. A feed outage still sends the default. The send log key is the America/New_York date (`show-day` / `YYYY-MM-DD`, or `schedule-change` / the skipped date), so a repeated cron run or a changed Podhome guid does not send twice. Attempts run at 7:15, 8:15, 9:15, 10:15, and 11:15 AM ET. A recipient who was not logged is retried on the next of those runs. Each run logs one `podcast alerts …` line with counts and an error class, and no addresses.

A one-off move or cancellation is a row in `show_schedule_override`, edited by an admin at `/admin/schedule`. Migration `0015_show_schedule_override.sql` creates that table. `skip_date` is the America/New_York date with no regular show. `show_start` is the replacement instant, or null when the night is cancelled. On the skipped morning the cron sends one "No live show tonight" and no "We're on today". On the replacement morning it sends one "We're on today". A cancellation sends only the skip note. The row stops affecting mail, the site notice, welcome mail, and the chat live window at midnight ET on the day after the later of those dates.

A monitor should `GET /api/alerts/status` with the same bearer at 12:15 PM America/New_York or later. HTTP 200 and `"ok": true` means the expected mail is logged for every opted-in recipient, or that today expects no mail. HTTP 503, or `"ok": false`, means it is short. The JSON reports `date`, `expectedKind`, `sent`, `expected`, and `error` (`short`, `recipients`, `timeout`, `provider`, `database`, `config`). It never includes addresses or secrets. HTTP 401 means the bearer is wrong.

`/comic/collection` is John's comic and movie collectibles. Migration `0011_memorabilia_frame_one.sql` inserts the first frame once, from `public/memorabilia/frame-01-batman-statue-v2.jpg`, and writes a `memorabilia_seed` marker. Deleting that frame does not bring it back. Admins can replace any frame's picture, edit its caption, or delete it. A static `/memorabilia/` file is never deleted from disk; only a Blob or a local upload file is removed when its picture is replaced.
